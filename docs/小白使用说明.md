# 小白使用说明｜全球每日新闻自动收集 + GitHub 归档 + QQ 邮箱推送

## 1. 每天会自动完成什么？

北京时间每天 **08:17**，GitHub Actions 自动开始执行：

1. 用公开 RSS / Google News RSS 在 29 个行业主题及 11 个地区主题中检索过去 24 小时的新闻；
2. 排除超出时间窗口的报道，合并多个分类中重复的标题，并记录抓取失败的来源；
3. 按来源链接输出中文综合日报（report.md）、完整结构化数据（data.json）、可用 Excel 打开的来源表（sources.csv）；
4. **先上传并提交**到本 GitHub 仓库；
5. 如果邮件服务已经配置好，再用 SMTP 发出邮件，邮件正文可以直接阅读，附件含完整 Markdown 日报和来源 CSV；
6. SMTP 成功接收邮件后写入 mail-sent.json，普通重复运行会跳过已发送日报。

文件存放方式：

```text
reports/年/月/日/report.md
reports/年/月/日/data.json
reports/年/月/日/sources.csv
reports/年/月/日/mail-sent.json
```

例如：`reports/2026/10/22/report.md`。

**注意**：本系统尽可能广泛覆盖而不是声称“所有国家所有行业所有媒体”。媒体数量、翻译、付费内容、时差、报道时间等都会影响覆盖。来源链接可能指向 Google News 跳转页。日报中的趋势研判默认关闭，没有 LLM Key 时提供按行业整理的可追溯事实摘要。

## 2. 让它真正给你的邮箱发信（必须配置）

打开你的仓库：

[GitHub 仓库设置 → Actions Secrets](https://github.com/mjw3177109/gezhongxinwenzongjie/settings/secrets/actions)

点击 **New repository secret**，创建下列两个必要密钥：

| Secret 名称 | 填写内容 |
| --- | --- |
| `SMTP_USER` | 你要用来发信的完整 QQ 邮箱地址（如 xxx@qq.com） |
| `SMTP_PASSWORD` | QQ 邮箱设置里开启 SMTP 服务后生成的**授权码**，**不是 QQ 登录密码** |

默认收件人等于发件邮箱（自己给自己发），SMTP 服务器默认是 `smtp.qq.com:465` SSL。

如果你想**发送到另一邮箱**，再增加：

| Secret 名称 | 填写内容 |
| --- | --- |
| `EMAIL_TO` | 接收报告的邮箱地址；多个用英文逗号隔开 |
| `EMAIL_FROM` | 可选，默认与 `SMTP_USER` 一致 |

若发送账号不是 QQ 邮箱，请在仓库设置 **Settings → Secrets and variables → Actions → Variables** 添加 `SMTP_HOST`、`SMTP_PORT`。目前支持 465 (SSL) 或 587 (STARTTLS)。

**绝对不要**把邮箱授权码写入代码、README、聊天截图或公开仓库。不要使用 QQ 登录密码代替 SMTP 授权码。

> 未填 `SMTP_USER` / `SMTP_PASSWORD` 时：日报仍可先归档 GitHub，但邮件步骤会明确报错，整个运行显示失败，**不能视为邮件已经发出**。

## 3. AI 深度分析（可选）

仅要**免费地进行 RSS 采集、分类、去重、摘要和归档**，无需任何大模型密钥，也不用部署服务器。

如果希望额外加入“跨行业趋势、机会风险、待关注信号”的中文研判，可以增加 GitHub Secret：

- `OPENAI_API_KEY`：你的 API Key（可能产生调用费用）
- 可选 Actions Variable `OPENAI_MODEL`：默认 `gpt-4.1-mini`

如果你倾向使用 DeepSeek API（不是 DeepSeek 网页版），可保持密钥名称 `OPENAI_API_KEY` 不变，但填入 DeepSeek 的 API Key，并在 Actions Variables 中填写：

| Variable 名称 | 示例值 |
| --- | --- |
| `OPENAI_API_URL` | `https://api.deepseek.com/chat/completions` |
| `OPENAI_MODEL` | `deepseek-flash` |

这是与 OpenAI 兼容的 Chat Completions 接口，使用时按 DeepSeek API 的实际计费与限额执行。参考 [DeepSeek 官方 API 文档](https://api-docs.deepseek.com/zh-cn/)。

AI 使用媒体标题、来源和时间作为证据；生成内容标注其性质并要求逐条引用原报道。由于未获取新闻全文，AI 研判不应作为正式事实核查或投资建议。如 AI API 发生错误，仍继续输出事实型日报。

## 4. 手动检查第一次是否运行成功

1. 打开 [Actions 页面](https://github.com/mjw3177109/gezhongxinwenzongjie/actions)；
2. 找到 **全球全行业每日情报**；
3. 点击 **Run workflow**，选 `main` 后启动；
4. 检查运行日志，重点看“实际抓取并生成日报”“先提交日报到 GitHub”“SMTP 投递日报邮件”；
5. 查看 `reports/年/月/日/` 是否出现三个报告文件；邮件成功时还会出现 `mail-sent.json`。

**提醒**：本项目工作流创建不等于已在你 QQ 账号开通了 SMTP 授权，也不等于已实际完成一次云端全流程成功运行。第一次必须检查 Actions 日志和收件箱（含垃圾箱）。

## 5. 常见问题

**Q：是不是所有国家和所有行业的新闻？**

不是。现有配置覆盖 29 个行业与 11 个区域观察主题、8 个直连媒体 RSS，含英语、中文、日语、韩语、西班牙语检索。你可以编辑 `config/topics.json` 扩展主题和媒体来源。摘要中的报道数不是全球真实新闻数量。

**Q：它几点发？**

北京时间每天约 08:17（UTC 00:17）。GitHub Actions 的 schedule 可能延迟，甚至在高负载时跳过；如果要求完全 SLA，请使用外部定时器作为备用调度。

**Q：为什么没有收到邮件？**

先查本日 `mail-sent.json` 有没有生成，再看 Actions 日志。一般原因：QQ 邮箱尚未开 SMTP、授权码错误、发件人地址不符合服务商限制、邮箱拦截、发送限额、定时任务未启动。

**Q：重复点击 Run workflow 会连发多封吗？**

正常情况下，不会。同日报告默认不重抓，同日邮件若已有成功标记便跳过。注意 SMTP 发送与 GitHub 提交回执不是同一个原子事务，极端情况下“SMTP 已接收但回执还没提交就崩溃”会有重发风险；无法承诺数学上的严格一次性。

**Q：能补一个月前的历史日报吗？**

这个版本只采集运行时最近 24 小时的实时公开 RSS，**不支持历史回填**。不能把今天的报道冒充一个月前的新闻。

**Q：想换成晚间日报、PDF、行业单独附件怎么办？**

修改 `.github/workflows/daily-report.yml` 的 cron、或增加后处理即可。别忘了 cron 默认用 UTC。

## 6. 程序本地运行

需要 Python 3.10+（推荐 3.12）：

```bash
python -m unittest discover -s tests -v
python src/daily_digest.py
# 仅在配好邮件环境变量后执行：
python src/send_email.py
```

报告只保存公开新闻的标题、RSS 摘要和原始链接；不会绕过付费墙或全文转载。
